# Registro de decisiones pendientes

## Metodología de evaluación

- Definir dimensiones de calidad observable.
- Definir criterios verificables por dimensión.
- Definir evidencia mínima requerida.
- Definir tratamiento de incertidumbre.
- Definir límites de interpretación mediante IA.

## Calificación

- Definir escala.
- Definir pesos.
- Definir fórmula.
- Definir umbrales.
- Definir relación entre hallazgos y calificación.
- Validar reproducibilidad y consistencia.

## Arquitectura

- Seleccionar estilo arquitectónico.
- Definir límites de módulos.
- Seleccionar mecanismo de persistencia.
- Definir ejecución aislada de Playwright.
- Definir estrategia de configuración y secretos.
- Definir observabilidad.

## Automatización

- Seleccionar patrón de abstracción de UI.
- Definir estrategia BDD/TDD.
- Seleccionar framework Cucumber compatible con el stack final.
- Definir niveles de prueba.

## CI/CD

- Definir workflows.
- Definir quality gates.
- Definir política de ramas y PR.
- Definir artefactos de evidencia.

Ninguna decisión pendiente deberá considerarse aprobada por defecto durante la implementación.
